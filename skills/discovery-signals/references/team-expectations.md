# Team expectations

Optional. Ask before any analysis, so whatever the team already believes is on record before the AI's report can shape it. These are the team's beliefs and intuitions, not the testable hypotheses that Step 5 writes from the data. Many teams arrive with none; that is fine.

## The question

Ask it once, as one question in the round format, with no recommendation of what to believe:

```markdown
**Q1** - **Any expectations before we look?**: Before I show you anything, do you already expect the data to show something: a problem, who has it, or why? List as many as you like. If nothing comes to mind, say skip and I'll go straight to the data.

**Recommendation:** Skip is fine. Any expectation you list gets a verdict in the report.
```

Take what the team gives, as given. If an expectation names no segment or reason, keep it that way; do not ask follow-ups. If the team says skip or has none, write the file below with the "none" line and move on in the same message.

## Format

Turn each answer into one line the data could prove wrong, keeping the team's words:

> We expect [segment] to [problem], because [what the team has seen].

## Output

`discovery/[project]/signals/team-expectations.md`:

```markdown
# Team expectations: [product]
**What this is:** our expectations, written [date] before we looked at the data. The Signal Analysis Report gives each one a verdict. The open questions the data raises are in `hypotheses.md`.

- **E1.** We expect ... because ...
- **E2.** ...
```

With no expectations:

```markdown
# Team expectations: [product]
No expectations recorded before the analysis ([date]). The open questions the data raises are in `hypotheses.md`.
```

The Signal Analysis Report compares each expectation with the data in its "What the team expected" section. Do not edit this file after the analysis runs.
