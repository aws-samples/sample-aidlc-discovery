# トレーナー養成研修: 2 時間のリモート研修のチャット台本

> この文書は [facilitator/train-the-trainer-chat.md](../train-the-trainer-chat.md) の日本語訳です。v3.0.0 の原文をもとにしています。内容が食い違う場合は原文を優先します。

ビデオ会議のチャットに投稿するメッセージを、投稿する順に、そのままコピーできる形で載せます。時刻は `train-the-trainer.md` の「2 時間のリモート版」に合わせてあります。[角括弧] の部分は置き換えてください。

## ビデオ会議の前（前日）

```
明日の AI-DLC Discovery トレーナー養成研修の事前準備です。所要時間は約 20 分です。研修の時間をインストールではなく練習に使えるよう、今日のうちに済ませてください。

1. 送ったパックを解凍してください。ファシリテーターを務める人はファシリテーターパック、それ以外の人は受講者パックです。
2. AWS Quick Desktop で、カスタマイズ（Customize）> スキル（Skills）> 作成（Create）> フォルダから（From folder）の順に選び、パックの中の aidlc-discovery フォルダを選んでください。
3. 新しいチャットを始めて「スキルの一覧を表示して」と入力してください。このメッセージに返信して、結果のスクリーンショットを送ってください。AI-DLC Discovery が表示されるはずです。
4. パックの中の anycompany-air フォルダを開き、シナリオページの README.md を読んでください。ほかのものは読まないでください。答えはデータの中に隠されています。
5. パックの中の role-cards.html を開き、自分のカードを見つけてください。
6. 前半のファシリテーター: チームの共有スペースを作り（スペース（Spaces）> 作成（Create space））、チームの名前をつけ、サンプルをそこにコピーし（facilitator/dry-run-air.md の手順 0 にあるコピー用のプロンプトを使います）、所有者（Owners）としてチームに共有してください。全員: チームの共有スペースを新しいチャットに添付してください（+ メニュー > スペース）。

チームと役:
[チーム 1: ファシリテーターは [名前]（前半）と [名前]（後半）。[名前]: デジタル部門長。[名前]: エンジニアリングリード。[名前]: カスタマーサービス運用責任者。[名前]: 法人営業部長。]
[チーム 2: ...]
```

## 00:00 メインルーム

```
ようこそ。今日は、AI-DLC Discovery ワークショップを実際に進めながら、そのファシリテーションを学びます。最も大切なルールは、「アシスタントが下書きをして、決めるのはチーム」です。ファシリテーターの仕事は場を整えることです。時間を管理し、場の勢いを保ち、考えるのがチーム自身であるようにします。
```

```
ブレイクアウトルームのルール:
- 1 つのブレイクアウトルームに 1 チームが入ります。前半のファシリテーターが AWS Quick を画面共有し、dry-run-air.md（パックの facilitator フォルダの中）に沿って進めます。
- ほかの全員は、自分のロールカードの役を自分の言葉で演じます。その人物なら反論する場面では、反論してください。
- 00:45 に、後半のファシリテーターが場の進行を引き継ぎます。前半のファシリテーターは AWS Quick の共有を続け、後半のファシリテーターに頼まれたことを入力します。
- チームがフェーズを終えるたびに、このチャットに 1 行投稿してください。例:「チーム 2: Signals（顧客シグナルの分析）完了、カスタマーサービス運用責任者が異議を出した。」
- 振り返りの問いはここに投稿します。AWS Quick が作業している間に、スレッドで答えてください。
```

## 00:10 ブレイクアウトルームを開く

```
ブレイクアウトルームを開きました。前半のファシリテーター: AWS Quick を画面共有し、「スキルの一覧を表示して」と入力してから、dry-run-air.md の開始プロンプトを貼り付けてください。役を演じる人: 役になりきって、1 人 1 行で自己紹介してください。
```

## 00:15 キックオフと Signals

```
ファシリテーターへ: アシスタントは、チームの予想について任意の質問を 1 つします。それを読み上げて待ってください。いちばん口数の少ない人から聞いてください。
```

## 00:30

```
振り返りまであと 5 分です。分析がまだ続いている場合は、そのまま進め、答えられるようになったら答えてください。
```

## 00:35 振り返り 1（スレッドで答える）

```
振り返り 1。チームごとに 1 行で答えてください:
1. アシスタントは、分析を見せる前にチームの予想を一度だけ、押しつけずに聞きましたか。
2. イレギュラー運航（欠航や 2 時間を超える遅延など、予定どおりに運航されないこと）が最初に来ましたか。カスタマーサービス運用責任者の「人員の問題ではないのか」という異議と、エンジニアリングリードの決済のタイムアウトについての異議は、どう進みましたか。
3. データで外れたのは誰の思い込みでしたか。ファシリテーターは、その人の面目をどう保ちましたか。
```

## 00:45 後半のファシリテーターが引き継ぐ

```
交代です。いまから後半のファシリテーターが引き継ぎます。共有スペースがある場合: 引き継ぎプロンプト（「[スペース名] スペースの discovery/anycompany-air/PROJECT.md から、anycompany-air の AI-DLC Discovery を続けてください。[役割] として引き継ぎます。ペルソナから始めてください。」）を自分のチャットに貼り付けて、画面を共有してください。共有スペースがない場合: 前半のファシリテーターが AWS Quick の共有を続け、入力を担当します。次は、ペルソナ、重み、採点の順です。デジタル部門長による予約フローの上書きを除いて、「すべて同意」を使ってください。
```

## 01:00

```
チームでユースケースを 1 つ選んで先に進んだら、PR/FAQ（Press Release / Frequently Asked Questions。発売時のプレスリリースと、想定される質問への回答をまとめた文書）の下書きを頼みます。次の文を貼り付けてください:「いま PR/FAQ の下書きを作ってください。」下書きを待つ間に、振り返りの問いに答えてください。
```

## 01:10 振り返り 2（スレッドで答える）

```
振り返り 2。チームごとに 1 行で答えてください:
1. アシスタントは Signals から候補を加えましたか。チームは何を残しましたか。デジタル部門長の上書きは理由とともに記録されましたか。決定は変わりましたか。
2. 3D 座席マップはゲートで落ちましたか。
3. PR/FAQ ができたら: Today statement（現状の課題文）は、機能ではなく成果を指していますか。North Star（目指す到達点）は能力を指していますか。準備度チェック（PR/FAQ がプロトタイプに進める状態かを 7 つの問いで確かめること）の判定は何でしたか。
```

## 01:15

```
ブレイクアウトルームの残りは 5 分です。PR/FAQ の下書きがまだ終わっていなければ、そのまま実行を続けてください。続きを再開するときには、下書きができています。
```

## 01:20 メインルーム: デモ

```
お帰りなさい。最後まで実行した例を使って、このあとの流れをお見せします。プロトタイプ、ペルソナによる講評、決定、Discovery brief（Handoff で作る、開発の出発点になる引き継ぎ文書）です。質問は随時チャットに書いてください。
```

## 01:35 うまくいかないとき

1 つずつ投稿し、答えを待ってから、トレーナー自身の画面で立て直し方を見せます。

```
トラブル 1。チームの 1 人が「先にデータが何を示しているか見せてください。私たちが何を予想していたかは、あとで伝えます。」と貼り付けます。あなたは何と言いますか。入力してください。
```

```
トラブル 2。誰かが「プレスリリースをもっと長くして、機能ごとに節を設けてください。」と頼みます。あなたはどうしますか。
```

```
トラブル 3。誰かが「2 段落目に数字をもっと入れて、すべてに Known のラベルをつけてください。」と頼みます（Known は「データで裏付けあり」を示すエビデンスラベルです）。この依頼の何が問題でしょうか。どう立て直しますか。
```

```
トラブル 4。参加者が黙り込み、何にでも同意します。本物の異議を 1 つ引き出すには、どうしますか。志願する人は、ミュートを解除して試してください。
```

## 01:50 種明かし

```
投票です。チームごとに 1 行で答えてください: イレギュラー運航を最初に置きましたか。予約フローと決済のタイムアウトに流されませんでしたか。3D 座席マップは落ちましたか。どの落とし穴にはまりそうになりましたか。
```

## 01:55 宿題

```
宿題です。1 週間以内に済ませてください:
- ファシリテーター: チームの実行を Prototype から Handoff（引き渡し）まで続け（約 50 分）、決定とプロトタイプについての 5 分の報告会の発表を録画して、チームに共有してください。
- ほかの全員: dry-run-air.md のドライラン（一人リハーサル）を最後まで進めてください（約 2 時間）。
- そのあと: 実際のチームで進めるなら違うやり方をする場面を 3 つ書き出し、私に共有してください。
その次のステップ: 自分でワークショップを主導する前に、経験のあるファシリテーターと共同でファシリテーションしてください。ありがとうございました。
```
